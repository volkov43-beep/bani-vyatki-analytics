## Что реализовано в интерфейсе

- Верхние KPI: обращения, целевые, договоры, выручка.
- График нагрузки сотрудников и график их долей выручки.
- Сводная финансовая таблица, включая отдельную колонку «Маржа, ₽».
- Таблица 13 обезличенных договоров: дата договора, менеджер, источник, выручка и «Маржа по сделке, ₽» (пока «Не заполнено»).
- Фильтры по источнику и сотруднику распространяются на финансовые показатели и детализацию.
- Предварительные планы по марже без выдуманного факта.

**Важно:** никто не может редактировать и сохранять маржу в публичном прототипе. Поле станет источником данных из Битрикс24 после создания пользовательского поля сделки и синхронизации с сервером.

## Планы по марже и отсутствие факта

- 500 000 ₽ — исполнитель пока не указан.
- 300 000 ₽ — «Илья», уточнить конкретный ID сотрудника в CRM.
- 200 000 ₽ — «Михаил», уточнить соответствие учётной записи.

Сумма личных планов — 1 000 000 ₽, реалистичный план компании — 1 440 000 ₽; это не согласованная единая сумма. Общий факт маржи сентября известен — 1 240 000 ₽, но не распределён по сделкам, поэтому персональное выполнение планов не рассчитывается.

## Следующий этап — Битрикс24

Для автоматической маржи понадобится отдельное пользовательское поле в сделке (формат сумма в рублях) и согласованные правила расчёта. Менеджер заполняет маржу в карточке CRM, защищённый сервер читает значения через API и суммирует их. Доступ только на чтение для нашего дашборда.

GitHub Pages остаётся публичным прототипом. В файлах нет клиентов, телефонов, их email, внутренних ID сделок или webhook URL. Имена сотрудников и их выручка публично отображаются — это следует учитывать при дальнейшем использовании.
