# Раздел 04 — Менеджеры: методика, источники, ограничения

## Принципы расчёта

Раздел показывает **два независимых набора данных**, которые нельзя смешивать:

1. **Обращения за сентябрь:** 222 сделки, созданные 1–30 сентября 2026. Источник: обезличенная выгрузка CRM, поля «Ответственный», «Источник», «Стадия сделки», «Дата создания». Назначения соответствуют состоянию на момент экспорта, а не обязательно изначальному распределению.
2. **Заключённые договоры за сентябрь:** 13 договоров на 5 643 000 ₽ — уточнённый итог пользователя. Персонально распределены только 10 договоров на 4 318 000 ₽ из исходного сентябрьского отчёта (раздел 8). **Ещё 3 договора на 1 325 000 ₽ не распределены по сотрудникам.**

Показатель «Доля целевых» = обращения не в стадиях «Игнорит», «Спам.Различные предложения» и «не ответили после рассылки» / все обращения сотрудника за сентябрь. Он характеризует качество потока, а не чистую результативность менеджера: источники и сложность обращений различаются. Нельзя рассчитывать персональную конверсию как договоры, заключённые в сентябре, / обращения, поступившие сотруднику в сентябре: это **разные когорты**.

- **500 000 ₽** — пользователь не указал, какому именно менеджеру соответствует эта величина; сопоставление требуется.
- **300 000 ₽** — «Илья»; сопоставление с ID сотрудника CRM пока не подтверждено.
- **200 000 ₽** — «Михаил»; сопоставление с ID сотрудника CRM пока не подтверждено.

Сумма перечисленных планов **1 000 000 ₽** не равна реалистичному плану компании по марже **1 440 000 ₽**; не пытаемся принудительно их уравнять. Факт маржи компании за сентябрь — **1 240 000 ₽**, без персонального распределения. Процент выполнения персонального плана **не рассчитываем**, пока не будет фактической маржи по каждому менеджеру.

## Источники и безопасность

- Документ «Отчёт по маркетингу за сентябрь 2026», разделы 4, 8 и последующие корректировки пользователя.
- Файл «Лиды_CRM июнь-сентябрь 2026.xls» — срез сделок без личных данных клиентов.
- Публичный GitHub Pages — **только для демонстрации без клиентских имён, телефонов, email, ID сделок, доступа к вебхукам**. Имя сотрудника вместе с показателями эффективности тоже корпоративная информация; перед реальным использованием эту часть необходимо защищать авторизацией на Beget.

## После интеграции с Битрикс24

Потребуется получать историю ответственных и дату фактического заключения договора, привязать маржу каждой сделки к менеджеру, получить личные планы и дату выполнения, а затем считать персональную конверсию только по сопоставимым группам сделок. Это отдельный этап после согласования интерфейса.
