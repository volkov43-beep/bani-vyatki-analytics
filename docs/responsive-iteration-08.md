## 2. Запуск и воспроизводимость

Добавлены файлы:

- `scripts/test-dashboard-release.py` — сквозная браузерная регрессия на настоящих статических страницах, не на моках браузера;
- `.github/workflows/full-dashboard-qa.yml` — три независимых job: Chromium, Firefox, WebKit;
- `scripts/check-public-dashboard.mjs` — дополнительная проверка очевидных CRM-токенов/вебхуков/телефонных номеров в публичных HTML/CSS/JS;
- обновлённый `scripts/test-sales-browser.py` — склонение числа обращений проверяется по русским правилам.

Каждый job устанавливает `playwright==1.56.0`, запускает локальный HTTP-сервер и проверяет страницу без Bitrix API. Установлены минимальные разрешения GitHub Actions (`contents: read`). Скриншоты и JSON-отчёты сохраняются в артефактах **final-qa-chromium**, **final-qa-firefox**, **final-qa-webkit** (14 дней).

Локальный ручной запуск при наличии Playwright и движка:

    python3 -m http.server 8765 --bind 127.0.0.1
    BV_BROWSER=chromium python scripts/test-dashboard-release.py

Также:

    node scripts/check-responsive-foundation.mjs
    node scripts/check-navigation.mjs
    node scripts/check-public-dashboard.mjs

### Что конкретно проверено

1. Пять прямых URL, файлы ресурсов, отсутствие ошибок JavaScript.
2. Переходы между всеми разделами с проверкой активного пункта меню; мобильные открытие/закрытие/Escape и корректный переход.
3. Отсутствие горизонтальной прокрутки **всего документа** на тестируемых ширинах; локальная прокрутка таблиц/графиков допускается.
4. Согласованность 13 договоров, общей выручки 5 643 000 ₽, 222 обращений, 122 целевых и других итоговых данных сентября между несколькими разделами.
5. Сценарии реалистичный/оптимистичный, выбор Авито, переключение графика договоры/выручка, выбор сотрудника, фильтры, сортировка цикла.
6. Незаменяемость **неизвестной маржи по сделке на 0 ₽** в разделе менеджеров.
7. Даты 13 договоров в разделе цикла, средний цикл 11,5, медианный 9, корректность сортировки.
8. Семантическая структура (по одному h1 и main, пять активных ссылок, один текущий пункт, поле выбора с подписью).
9. Адресная проверка контраста **основных заголовков и подзаголовков** — фактически измеренные отношения в диапазоне от 5,29:1 до 11,08:1. Это не полный WCAG-аудит всех текстовых элементов.
10. При отсутствии JavaScript мобильное меню остаётся доступным; данные, генерируемые в JS, при этом не считаются независимой серверной реализацией.
11. Chromium: `prefers-reduced-motion` для прогресса и reflow-прокси **640→320 CSS px**, моделирующий эффективное уменьшение области при увеличении интерфейса. Это **не проверка нативного 200% масштаба браузера**.

## 4. Выявленные проблемы и исправления

**A. Контроль сквозной навигации.** Тест ошибочно ожидал `./index.html` в активной ссылке главного раздела; реально её корректный адрес — `#overview`. Поправлена проверка, а не работающая навигация.

**B. Русские окончания воронки.** В `sales.js` ранее использовалась проверка `total < 5`, которая давала неправильное окончание для 222 и 24 обращений. Добавлена функция склонения по последним цифрам: `222 обращения`, `167 обращений`, `21 обращение`, `24 обращения`. Правило проверяет и новый, и старый браузерный тест. **Никакие численные значения CRM при этом не менялись.**

## 6. Остаточные проверки до производственного развёртывания

- **Нативный zoom браузера 200%, text-only 200% и пользовательские интервалы** в Firefox/Chrome/Safari: автоматический reflow-прокси не является полной проверкой.
- Ручная проверка на **реальных iPhone Safari и Android Chrome**, включая открытие/закрытие меню и горизонтальный скролл касанием.
- Полный WCAG 2.2-аудит контраста всех элементов (в том числе нетекстовых), клавиатурного фокуса, доступных названий динамических SVG-графиков и экранных дикторов NVDA/VoiceOver. Автоматизированный тест текущего этапа охватывает только адресные проверки.
- Производительность на слабых устройствах, Lighthouse/Core Web Vitals, работа в медленных сетях; отдельного профиля на реальном устройстве пока нет.
- Безопасность: **GitHub Pages — общедоступная среда без авторизации**. В исходниках есть имена сотрудников и агрегированные финансовые показатели, это нельзя считать закрытой управленческой системой.
- Настройка поддомена Beget `analyticsbanivyatki.vermarkter.ru`, HTTPS, роли пользователей, read-only API Битрикс24, PHP/MySQL и защищённая синхронизация — **отдельный следующий проектный этап**.

Нельзя трактовать текущие «PASS» как проверку сервера Beget, Битрикс24, реальных устройств или соответствия всем WCAG критериями.
