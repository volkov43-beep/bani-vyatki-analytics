# Раздел 06 «ВКонтакте» — регламент ежемесячного обновления

Раздел показывает месяцы **с июля 2026 года**. Каждый новый месяц добавляется после его завершения, отдельным PR. Методика показателей — [docs/vk.md](vk.md).

## Кто что делает

| Шаг | Кто | Срок |
| --- | --- | --- |
| 1. Выгрузить файлы за прошедший месяц | маркетолог | до **3-го числа** следующего месяца |
| 2. Пересчитать показатели, сверить, обновить данные, открыть PR | Claude | до **5-го числа** |
| 3. Посмотреть PR и скриншоты, одобрить | владелец проекта | по готовности |
| 4. Объединение → публикация на GitHub Pages | автоматически после одобрения | в течение нескольких минут |

## Что выгружать (период — весь прошедший месяц, с 1-го по последнее число)

1. **Статистика сообщества ВК** → файл вида `217795299_community_common_ДД.ММ.ГГГГ_ДД.ММ.ГГГГ.xls`. Из него: подписки и отписки, число подписчиков, первые сообщения, посетители, охват по форматам и по подписчикам/неподписчикам.
2. **Контент ВК** → `posts_content`, `clips_content`, `video_content`, `story_ended` за тот же период. Из них: количество публикаций, охват и реакции каждой публикации, лучшие публикации, календарь.
3. **Рекламный кабинет ВК** → отчёт по кампаниям за месяц, **с разбивкой по дням**: расход, показы, клики, подписки, цель кампании, даты.
4. **Битрикс24** → сделки с источником «ВКонтакте», созданные в месяце, и договоры по ВКонтакте, заключённые в месяце (дата создания, стадия, сумма, дата договора).

Исходные файлы **не загружаются в репозиторий**: в них могут быть персональные данные (особенно в CRM). В публичный `vk-data.js` попадают только итоги.

Выгружать лучше после того, как месяц полностью закончился: статистика ВК за последний день появляется на следующие сутки.

## Как обновляются данные

1. **Сверка исходников.** Подписчики на конец месяца = на конец прошлого месяца + подписались − отписались (допускается пересчёт ВК на ±несколько человек — фиксируется в методике). Сумма охватов по форматам = итого охват. Дни, пересекающиеся с прошлой выгрузкой, должны совпадать. Договоры ВК из CRM = разделы 02 и 03 за тот же месяц.
2. **Новый месяц в `vk-data.js`:** добавляется объект в массив `months`, дневные значения — в `daily`, периоды рекламы — в `adPeriods`. Значения, которых ещё нет, записываются как `null` — на странице они показываются как «ждём выгрузку».
3. **Проверки:** утверждённые значения нового месяца добавляются в `scripts/check-responsive-foundation.mjs` и в словарь `EXPECTED` в `scripts/test-vk-browser.py` (тест требует, чтобы у каждого месяца из данных были утверждённые значения).
4. **Локальный прогон:** `node scripts/check-responsive-foundation.mjs`, `node scripts/check-navigation.mjs`, `node scripts/check-public-dashboard.mjs`, `python scripts/test-vk-browser.py`.
5. **PR** из ветки `feature/vk-data-ГГГГ-ММ` с таблицей новых значений и итогами сверки. GitHub Actions прогоняет тест раздела и общий тест всех страниц в трёх браузерах, скриншоты — в артефакте `vk-section-screenshots`.
6. **Не объединять без одобрения владельца.**

Вёрстка и логика страницы от количества месяцев не зависят: графики и переключатель месяцев перестраиваются автоматически, по умолчанию открывается последний месяц.

## Если каких-то файлов нет

Месяц публикуется с тем, что есть; отсутствующие показатели — `null` и пометка «ждём выгрузку». Когда файл приходит, значения дополняются отдельным небольшим PR.

## Дальше

После запуска серверной версии (PHP, MySQL, закрытый доступ) данные можно получать автоматически через API ВКонтакте (статистика сообщества, публикации, рекламный кабинет) и API Битрикс24 — только на чтение. Токены хранятся на сервере и никогда не попадают в GitHub.
